# 基于vibecoding的教学案例——老人防摔

> 一份可直接搬进课堂的项目式教学案例。本项目的**绝大部分代码（电脑端检测、模型训练脚本、安卓 App、报警推送、打包部署）全部由学生通过自然语言驱动 AI 完成**，是 Vibe Coding 全栈实践的真实样本。学生角色：提需求、验收效果、反馈问题、管理代码仓库。

---

## 一、案例概述

| 项目 | 内容 |
|------|------|
| 案例名称 | 老人防摔智能识别系统 |
| 课程适用 | Vibe Coding / AI 协作编程 / 人工智能实践课 |
| 覆盖技术 | YOLO 姿势估计、迁移学习微调、OpenCV、HTTP 推送、MJPEG 视频流、Android App、PyInstaller 打包 |

## 二、系统整体逻辑（先讲透"做什么"）

### 2.1 系统全貌

```
【感知层】USB摄像头
    ↓ 实时视频流
【检测层】电脑端 (Windows, Python + YOLO26n-pose)
    ① 姿势估计：每帧提取人体 17 个关节关键点
    ② 姿态分类：由躯干角度+框体形状 → 站立/坐着/弯腰/躺倒
    ③ 跌倒确认（核心算法）：人刚变成"躺倒"时，回溯前 2.5 秒——
        · 躯干角速度 > 60°/秒？（摔倒是"快速倒下去"的）
        · 重心下落速度 > 0.3 画面高/秒？（接近自由落体）
        · 躯干是否贴地？（弯腰摸地 ≠ 摔倒，肩和头还悬着）
      三条同时把关，"自己慢慢躺下/睡觉"天然被排除
    ↓ 确认摔倒
【报警层】本地蜂鸣+红色警报+自动截图
    ↓ HTTP 推送 (ntfy 云管道)
【接收层】手机 App（自研安卓应用）
    响铃+震动 → 亮屏弹出红色全屏警报（含现场截图）
    → 5 秒后自动拨打家属电话 → 可一键打开实时监控画面
```

### 2.2 课堂教学要点：为什么"摔倒检测"是个算法问题

单看一帧画面，**摔倒和睡觉长得一模一样**（人都是横着的）。区别在"过程"：

| 维度 | 摔倒 | 睡觉/自行躺下 |
|------|------|--------------|
| 时间 | 1~2 秒内从站到躺 | 十几秒慢慢躺下 |
| 运动学 | 角速度、下落速度爆表 | 两项指标都很低 |
| 空间 | 摔在地板任意位置 | 躺在床上 |
| 后续 | 挣扎或不动 | 有翻身等微动作 |

这个表格是本案例最重要的教学板书——它让学生理解：**智能系统识别的不是"状态"，而是"事件"；事件必须用时间序列来判断**。

## 三、Vibe Coding 贯穿全项目（真实过程）

本项目完整展示了"从零到成品"的每一步如何用 AI 协作完成：

| 阶段 | 学生说的话（真实话术） | AI 完成的事 |
|------|----------------------|------------|
| 起步 | "yolo可以识别人体姿势吗" | 讲解 + 装环境 + 跑通验证 |

| 模型训练 | "老师叫我试一试模型训练，我是A卡" | 找数据集→核验标注→写训练脚本→CPU 48分钟训完 |
| 安卓开发 | "我需要一个手机App收报警" | 生成完整 Kotlin 工程，学生只需用 Android Studio 编译 |
| 打包交付 | "编译最终版" | PyInstaller 打包 exe，修复依赖缺失报错 |

**课堂讨论题**：上表中哪些环节 AI 替代不了人？（答案：提需求、判断效果对不对、决定方向、测试验收——全是"人"的活）

## 四、GitHub 仓库习惯（本项目重点强调）

Vibe Coding 时代，**Git 不是可选项，是安全带**。本项目教学中学生必须养成：

### 4.1 为什么要用 GitHub 仓库

1. **AI 会改坏东西**（真实事故：AI 批量替换文本时把整个脚本搞成乱码，工作差点丢失）——有 commit 就有后悔药
2. **每个里程碑一个 commit**：commit message 写清楚"这轮让 AI 做了什么"，仓库历史就是你的开发日志，写论文时直接翻
3. **GitHub 远程仓库 = 异地备份 + 成果展示**：答辩时老师扫码就能看你的项目演进史，比任何 PPT 都有说服力
4. **协作基础**：小组项目多人 + AI 同时改代码，没有版本管理必然混乱

### 4.2 课堂强制要求（建议纳入评分）

```bash
# 每完成一个可运行的里程碑，必须提交：
git add .
git commit -m "完成姿势识别demo：能画出骨架并分类站/坐/躺"
git push
```

- 里程碑清单：跑通检测 → 跌倒判定 → 模型训练完成 → 报警打通 → App 可用 → 打包完成
- 检查方式：看 GitHub 仓库的 commit 时间线是否与论文描述的开发过程吻合

## 五、用 Vibe Coding 做安卓应用开发（特色章节）

本项目的学生**没有任何 Kotlin/安卓基础**，但产出了一个功能完整的报警 App。教学要点：

### 5.1 安卓开发的 Vibe Coding 流程

```
学生用中文描述需求（"收到推送要响铃、震动、全屏弹窗、显示现场照片、5秒后自动拨号"）（并下载Android Studio）
    ↓
AI 生成完整 Kotlin 工程（Activity/Service/权限清单）
    ↓
学生用 Android Studio 打开 → 点 Run/Build → 出 APK 装到手机
    ↓
真机测试 → 把现象描述给 AI（"一挂后台就断线"）→ AI 分析是国产ROM杀后台 → 给出电池白名单方案
    ↓
循环迭代直到可用
```

### 5.2 安卓特有坑的教学点

| 现象 | 根因 | 解决 |
|------|------|------|
| App 一切后台就收不到推送 | 国产 ROM 激进杀后台 | 前台服务+通知栏常驻、电池"不限制"、最近任务加锁、自启动权限 |
| 收不到警报 | 通知权限没开 | Android 13+ 需运行时申请 POST_NOTIFICATIONS |
| 不自动拨号 | CALL_PHONE 权限被拒 | 代码里降级为跳拨号盘（优雅降级思想） |
| 锁屏不弹警报 | 需要全屏 intent 权限 | setShowWhenLocked + 引导用户授权 |

**教学点**：移动端开发的大部分"坑"不在语法，在系统机制和权限。AI 知道所有这些坑——学生学会问"为什么后台会断"比学会写 Service 更重要。

### 5.3 给学生的"需求描述"示范话术

> "我要一个安卓 App：①后台常驻订阅 ntfy 的 xxx 主题；②收到高优先级消息时响铃+震动+全屏弹红色警报页；③警报页显示推送附带的图片；④填了紧急电话就 5 秒后自动拨打；⑤有个页面能看 MJPEG 监控画面。"

——这一段话就产出了一个完整 App。让学生体会：**描述能力就是编程能力**。

| 课时 | 内容 | 里程碑 commit |

## 七、评价量规（百分制）

| 维度 | 权重 | 要点 |
|------|------|------|
| 系统功能 | 25% | 检出摔倒、区分睡觉/弯腰、报警链路通 |
| GitHub 仓库 | 15% | **commit 历史完整、message 有意义、与论文过程吻合** |
| 模型训练 | 15% | 完成微调、读懂指标、有对比实验 |
| 过程文档 | 25% | 论文记录真实迭代（含失败尝试） |
| 答辩 | 20% | 能讲清系统整体逻辑与核心算法——**"代码是 AI 写的，道理必须是你懂的"** |

**红线**：讲不清自己系统原理者，功能分打折。
